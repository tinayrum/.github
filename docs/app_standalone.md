## 概要

本ガイドは、Portalリポジトリと連携せず、アプリケーションリポジトリ単体で運用する場合の手順・ルール・注意点をまとめたものです。

---

## 1. 単体運用の主なケース
- 小規模・単機能アプリの開発
- 検証用・PoC開発
- Portal統合前の初期開発

## 2. ディレクトリ構成例

```
RepoRoot/
├── .github/      # CI/CD 設定
├── src/          # ソースコード
├── docs/         # ドキュメント
│   ├── index.md
│   └── images/
├── tests/        # テストコード
└── README.md     # QuickStart
```

## 3. 運用ルール
- **Docs as Code**: コード修正時は docs/ も必ず更新
- **main直Push禁止**: PR経由でマージ
- **CI/CD必須**: GitHub Actions等で自動テスト・デプロイ
- **README.md整備**: QuickStart・開発手順・依存関係を明記

## 4. Portal連携への移行
- 必要に応じて、後から Portalリポジトリへ subtree 連携可能
- 連携時は、docs/ の内容も統合されるよう整理

## 5. 注意点
- Portal連携がない場合、組織横断のナレッジ共有・統合管理は行われません
- セキュリティ・運用ルールは各リポジトリ単位で遵守

---

## よくある質問

!!! question "Portal連携は必須ですか？"
	小規模・短期開発や検証用途では単体運用も可能です。  
    組織的なナレッジ共有が必要な場合はPortal連携を推奨します。

!!! question "後からPortal連携できますか？"
	可能です。docs/やCI/CDの構成をPortal標準に合わせておくとスムーズです。
